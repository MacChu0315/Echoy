# 技能行为评估

## 当前状态

**未执行。** `cases.json` 是待运行的合成任务与评分条件，`runs` 为空。包检查只检查资料结构，不冒充 agent 测试。本环境没有可调用的独立 agent 执行器或可运行的 Codex CLI；未安装外部服务或调用付费模型补测。

## 运行方法

每个案例分别开无 skill、有 skill 两个独立会话，固定模型、工具权限、时间预算和输入。无 skill 组不加载本包正文、参考、候选稿或评分标准；有 skill 组只提供对应技能与自身参考。两组共同保留目标项目原有规则。

只把 `prompt` 发给受测 agent；`acceptance`、`failure_signals` 留给评审。先观察无 skill 组的具体失败，再运行有 skill 组。每组至少重复两次，保存原始输出、工具调用、产物和执行环境，不用会话概述代替证据。

误触发案例只提供技能名称与描述，不强制加载正文；正例除执行检查，也单独观察仅有名称／描述时是否能选中技能。不要把显式加载后遵循指令等同于自动触发正确。

缺失目标的案例故意不提供文件，不能补造。文字测量案例只要求依据给定事实判断，不假装见过作品。进一步评估实际修改时，固定真实输入与初始状态，并检查产物行为。

## 评分

逐条记录 pass、fail 或 blocked，附原始输出／产物位置。说“我会检查”不算实际检查。条件不支持执行时，正确说明限制与实际验证完成分别评分。语义条件由评审判断，不用关键词出现次数当效果评分。

同时记录额外追问、无必要文档、依赖、越权写入和超时。检查非音乐项目是否被强加 Echoy 角色、小节、单机或整组控制规则。触发结果、行为结果与包格式结果分开汇报。

真实运行后单独记录案例 ID、组别、重复序号、模型／客户端版本、技能提交号、输入、原始输出路径、各条件结论和阻塞，再更新执行状态。一次结果不足以证明通用有效。
