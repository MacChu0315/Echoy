# Echoy GSP application

The native desk and firmware compile shared C UI, composition, arrangement,
synthesis and scheduling sources under `main/`. See the [workspace README](../../README.md)
for the audible desk, diagnostics and fixed-SDK build commands.

- `echoy_music` ports the twelve single-tile expressions.
- `echoy_arrange` ports structured upstream adaptation, graph validation,
  detach retention, independent play permission and logical clock ownership.
- `echoy_audio` renders immutable 24kHz SOURCE/FOREGROUND/FULL buffers and cues.
- `echoy_band` coordinates managed recording models, preparation jobs,
  revision cancellation, linked commits, sample mixing and gain changes.
- `echoy_ui` copies controller snapshots to its owner thread; Canvas/resources
  never borrow concurrently mutated musical state.
- `pc/desk_main.c` supplies three GSP owner threads, one preparation worker,
  one PCM output thread, installed PulseAudio output and private desk controls.
  It copies snapshots under the band lock and performs file I/O after unlocking.

`ui/main.json`, the page contract, view keys and assets are generated by
`../../tools/generate_scene.py`. Home art uses two Canvas callbacks; gallery art
uses runtime QOI images from the same renderer. Image completion is tracked
separately from submission, and cleanup retains callback contexts until drained.

The physical app entry still uses the UI-only platform adapter. Board audio,
discovery, real communication/clocks and hardware readings require subsequent
integration and verification. Do not install this as a finished device build.
The retained Vibe Mode/Recovery integration follows the official template.
