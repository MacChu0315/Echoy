## 4. 技术路线

建议选 **hello_world + LVGL 9 + 独立 C 规则核心 + 本地 DSP + BSP 无线适配**。

- LVGL 已在 hello_world 与 BSP 中，现有示例实际使用 `lv_display_t` 等 9.x API。新应用约束 9.x，保留解析后的依赖锁定结果；不修改参考模板来兼容 8.x。
- 界面结构和控件用 LVGL；四种动态图形用与原 `DuijuView.draw()` 对应的绘制代码，图形和音频读取同一小节计划。
- 音符生成、会话与状态变化写成不依赖 ESP-IDF/LVGL 的 C 核心，便于 PC 与 MCU 共用，并与 JS 对照。
- 音频移植 Web Audio 的合成、滤波、包络与延迟效果；BSP 只提供音频输出基础，不存在可以直接替代原合成器的现成 MP3 示例。
- UI、状态、音频、无线通过有界队列和不可变快照交换。音频任务不能等待 UI 锁、无线重试或磁场读取；无线回调只复制消息入队。

备选：GSP 1.2.0 有现成 PC 仿真，但连续曲线、颗粒和动态和弦仍需核对其绘制能力，并引入场景打包及分区处理；本任务优先采用现有 LVGL 路径。ESP-Claw 整体改造会引入与复刻无关的产品运行时，本工程沿用不导入该运行时的设计约束。Vibe AGENTS 是使用其工具/组件时的参考；它不作为同级 Echoy 的目录作用域规则，用户指定的工程位置优先。

## 6. 音乐与交互契约

| 角色 | 三个乐句 | 初始表达 | 首次选入乐句 |
| --- | --- | --- | --- |
| Pulse / 脉冲 | 重音、切分、留白 | .58 | 1 |
| Voice / 声线 | 短句、轻答、长线 | .56 | 1 |
| Dust / 微尘 | 颗粒、点缀、余韵 | .48 | 1 |
| Harmony / 和声 | 短和弦、分解、接句 | .50 | 2 |

- 96 BPM，4 拍/小节，16 步/小节；一步 156.25ms，一拍 625ms，一小节 2.5s；D 小调词汇及原来的音符、重音、时长规则全部保留。
- 区分 `activity` 与 `committedActivity`。拖动立即更新图形、音色和新调度音符的时长表达；节奏密度/落点在小节边界生效。音量独立，不能将“丰富”实现成更响。
- 本机音量默认 .70；浏览器还有 .55 的预览主增益，这是电脑混音设置，不是共享的真机音量参数。
- 播放请求进入 waiting，在下一拍启动；暂停立即停止本机发声，并取消 waiting。不因相邻设备播放、合并会话或重新发现而替用户开始播放。
- 角色和乐句按原型保存各角色的选择记忆。切角色准备时旧声音继续；准备成功后排队，在下一小节切换；失败保留旧角色；取消清除相关候选操作。
- 若整个逻辑会话的成员均暂停，`commitIdle()` 可立即提交参数。仅本机暂停而其他成员演奏时，仍等待共同小节。
- 乐句来源只取已生效的直接左邻完整 `motif`，包含弱音、时长、留白和音高/和弦元数据；不能只传重音、用链头替代左邻，或让右侧反向修改左侧。
- `events` 是实际发声，`motif` 是供邻居回应的乐句。暂停、音量 0、扬声器输出故障不删除有效 motif；数据失效/素材 loading 才在边界改变 motif 可用性，并使右邻在相应边界退回独奏。
- 输出错误清除后，如果之前仍是 playing，可恢复原播放意图；用户已经暂停或设备重启后不能擅自播放。数据恢复必须等 motif 可用性边界。
- 重复角色的音域处理按原 `duplicate` 计数；Harmony 三个变体的时长上限、和弦择配、1–3 音以及分解/短和弦/接句的不同收尾全部保留。
- 原型算法是确定性的；C 必须匹配 JS 的负数取模修正、`Math.round`、稳定排序与平分时选择顺序。不可随意改成“近似音乐规则”。

## 7. 会话、磁吸和同步契约

稳定无线身份使用已核对的 `mosaico_peer_link_get_device_id()`；每次启动使用新的 `mosaico_peer_link_get_boot_id()`。ESP-Iris Device ID/Boot ID 属于设备运维身份，记录映射，不假设与无线身份数值相同。A/B/C 仅是电脑显示别名，不烧成三台重复的固定 UID。

1. 开机独立时间、暂停，发现附近候选不等于加入同场。
2. 磁吸可靠确认并识别正确无线对端后，交换时间信息；多个会话优先采用成员较多的会话，同数按参考成员稳定 UID 排序。在未来小节边界接入。
3. 拆开只在边界解除回应关系；无线仍可达时保留共同时间和成员关系。
4. 位置不确定保留当前关系一段有界时间；失联先保拍，超过保持窗口退回连续的本地时间，不能倒退或补播旧音。
5. 参考成员掉电：剩余成员按确定性规则选参考，保持时间连续；重启设备携新 boot ID 重新协商；旧启动周期消息、旧会话、旧事务不允许生效。
6. 同步失败保留原演奏并提示；重新具备可靠条件后协商，不能伪造成功。
7. 原型支持三台、左右链。固件不自行扩展为 BSP 支持的 16 台/任意二维拓扑；上下接触、环、方向不一致、重复边、第四台加入必须明确拒绝或报告，不能静默重新排列。

原型的 .38s 开机、.45s 接触、1.05s 同步准备、1.8s 保持、.65s 换角加载、2.6s 注入加载都是演示时长。电脑对照测试保留它们；真机 readiness 必须来自实际结果，尤其 1.05s 不能作为“已经测得同步”的证据。1.8s 保拍从应用心跳判定失联时起算，不能直接等同 BSP 2.5s 邻居 stale timeout。

### 已知 BSP 差异与补齐方式

- `mosaico_network` 应用有效负载只有 **64 bytes**；`mosaico_peer_link` 有效负载 **100 bytes**。不能把完整 JSON 或整条多音轨乐句一次发送。
- `mosaico_network` 收到 APP_DATA 时要求来源仍是当前邻居，因此不能只靠它维持拆开后的共同拍子。
- 建议让 `mosaico_network_start()` 唯一拥有无线初始化和物理邻居握手。Echoy 应用使用已有 `GAME_EVENT` + `raw_message_cb` 发送带 magic/version 的不依赖物理邻居的演奏协议；复用 `mosaico_peer_link_send_broadcast[_to]()`，不再次 init 无线。回调对 GAME_EVENT/DIAGNOSTIC 的实际入口已核对；不用 DIAGNOSTIC 队列承载演奏实时消息。
- 同场成员同步角色/乐句/表达/有效性/邻接版本，三台本地计算同一条链，再各自输出自己的声音；共享算法版本必须一致。不传音频流，不把麦克风当乐句来源。
- 用应用心跳和时间戳交换继续联系已入场成员；仅有发现广播的陌生设备不能获得会话成员资格。
- 双 BMM150 分类只能给接触证据，不能凭磁场强度/RSSI 推断唯一无线 UID。BSP README 要求一次新增一条尚未识别的边；同时首次夹入中间设备存在对端歧义。安全实现应提示接触待确认，分次吸合能继续。要消除该限制需要额外可靠识别方法，不能只调整阈值或假装已实现。
- 推荐先限定三台在彼此无线可达范围内；超出这一条件按失联处理。跨多跳保持逻辑会话不在当前原型的无线实测能力内。

## 8. 音频执行与并发

使用 `bsp_audio_codec_speaker_init()`、`esp_codec_dev_open()`、`esp_codec_dev_write()`；参考 `audio_loopback/main/main.c` 的返回值处理。输出初始选 48kHz、16-bit、双声道格式（BSP 默认），本机声音按实际扬声器通道映射；不启用麦克风。

移植六种事件 kick/rim/hat/tone/grain/chord 的振荡器、滤波、包络、固定种子噪声以及每台独立的 wet tail。区分和弦时长与 tone/grain 的余韵。原型共用浏览器限幅器不能证明各台扬声器音色一致；MCU 输出需本地限幅和扬声器听测。

调度使用单调微秒时钟映射到输出样本编号，在音频块内部准确触发；不能用 LVGL timer 或普通任务唤醒点直接决定起音。已排入旧时间世代的事件必须失效；长期时钟校正不能造成重复音、漏一整拍或重播积压。表达/音量更新采用平滑，预分配声部和队列，运行中不逐音分配堆内存。

每帧 RGB565 为 460,800 bytes；双帧为 921,600 bytes；342×218 图形缓冲为 149,112 bytes；若按 HTML 2×分辨率渲染再采样，需 596,448 bytes。是否使用 2×由性能测试确定，不得把 PSRAM 可用量当作已测事实。不要在音频中断或 DMA 路径里做截图或 Unicode 字体加载。

## 9. 硬件与应用边界

- 电量来自 `bsp_battery_read()`，<15% 显示“请充电”；读失败不当作 0%，保留上次值并在诊断报告。0% 关停按 BSP 实际电源能力验证，绝不擦除系统数据。
- IMU 和扩展模块只提供诊断识别，不能新增“倾斜改变丰富度”的逻辑。摄像头不自动打开；不为了原型里的模块下拉选项独占扩展槽。
- 默认固件中文、Pulse、暂停；首次启动可通过角色页选择任意角色，演示三台时设置为 Pulse/Voice/Dust。不根据 MAC 尾号随机指定角色。
- 为对应模拟器收起/上桌保留设备设置的行为，建议使用应用 NVS 保存已提交角色、角色记忆及音量；不保存 playing、候选角色、session、boot ID 或待提交事务。写入应去抖，并与系统 `sysmeta` 隔离。这是真机关机适配建议，原 HTML 本身只在内存保留这些设置。
- 英文是完整支持的第二语言。原型语言入口位于电脑外层；建议固件用本地配置/开发入口切换，不新增第四个产品页面。若用户希望脱离电脑直接在设备上切换语言，需要另行确定入口。
- 保留 hello_world 分区表、`esp_mosaico_app_recovery`、`CONFIG_ESP_IRIS_OTA_DEFAULT_VIA_RECOVERY=y` 与 `iris_ota_support_start()`。正常应用不带 OTA writer。
- UI/音频失败后仍应保留 ESP-Iris 可诊断/可恢复入口，不能用全局 abort 使已可用的恢复服务消失；不得把未初始化音频报告为演奏正常。

## 10. 完成条件与风险

“完整复刻”必须同时满足：页面齐全、行为与原型对照、真实本机合成、三台真实同步与拆开保拍、故障恢复、Recovery 可返回。只有截图或单板演示均不够。

建议验收目标（设计目标，尚未实测）：控件位置误差不超过 2px；产品区域无缺字/裁切/触摸穿透；触摸确认 <=100ms；正常演奏 UI 约 30fps；连续三台演奏 30 分钟不发生音频欠载、看门狗重启或持续堆增长；扣除测量摆位/声传播误差后起音偏差 P95 <=10ms、最大 <=20ms。若设备做不到，记录数据并提交具体调整方案，不擅自放宽指标。

有限无线网络无法在任意丢包/分区下保证所有成员绝对同时提交。协议测试必须覆盖最终提交消息丢失；检测成员版本不一致后保持/降级并暴露状态，不能宣称两阶段消息天然解决了无线原子提交。

本轮验证：原 JS 音乐规则 1,200 个组合、4,892 个事件的合法性检查通过（该组合最大 12 事件）；独立启动、吸合合并、拆开保留会话、无自动播放检查通过；浏览器完成角色、音量、Harmony 切换和中英文截图。没有进行声学验证、固件构建或设备安装。页面仅有本地服务未提供 favicon.ico 的 404，未观察到应用脚本错误；不据此声称全部原型路径均已测试。
