# Echoy v1.2.0

This local release freezes the accepted phrase pickup and UI corrections on top
of v1.1.0. GitHub publication and integration into `master` are pending. The
published v1.1.0 release and its existing tags/assets remain unchanged.

## Changes from v1.1.0

- Add one or two quieter pickup notes when a recorded phrase starts with a rest.
  Empty input and first-step input are unchanged. Pickup is a local playback
  layer; source taps, original events, upstream/fallback plans and the wire
  protocol are unchanged. Original PCM from the first input onward is preserved
  with the same voicing configuration.
- Keep pickup artwork and grid feedback aligned with the actual sounding bank,
  including the local reply that starts before group activation.
- Display the complete `100%` battery text on all six pages.
- Keep the richness thumb at the latest requested position while the controller
  catches up. Rejected queued edits explicitly release pending UI feedback.

Three-device repair, shared Flash calibration, joined startup, local early
recording replies, role-aware random audition, input limiting, office voicing
and per-device Play/Pause are retained. The version-freeze step changes only
version identifiers and generated About/default text relative to the accepted
baseline. The app header, bundle release and device About version are `1.2.0`.

## Validation and acceptance scope

The accepted baseline's listening and UI behavior were approved before freezing
this release. The 1.2.0 build passed:

- `sh tests/pickup/run.sh`: 2,772 C/HTML event cases, 24 exact mix cases, 288
  office PCM pairs, 24 published transitions, audition compatibility and early
  three-owner replies, including rejection/failure/cancellation boundaries.
- Band playback/audition, all-six-order group, commit-pressure and exact
  scheduler regressions.
- Battery font bounds and 60 UI regression groups.
- 54 production runtime test methods.
- 10 official native three-owner checks, including local early reply, follower
  audition, shared commits and exact paused silence.
- Fresh pinned firmware/native builds, bundle inspection and version-only
  application-diff verification.

The desktop's existing fallback remains "Local build" when its adapter supplies
no firmware version. Native hardware-mode About validation supplies the release
version through the same platform field used by the device; it does not change
that desktop behavior. Both Chinese and English hardware-mode About views show
1.2.0 in the official native simulator.

The exact package was installed on three devices through the official retained-
Recovery workflow. Each operation confirmed a healthy, validated target with
the expected ELF identity; live readback reported 1.2.0 with a new boot and no
application crashes. Bootloader hashes and the retained layout were unchanged.
Three-device reciprocal neighbors converged to the same graph; idle PCM
reported zero write errors and deadline misses. Actual home-screen captures
show the complete `100%` text. This freeze reruns
installation/startup checks; listening and slider usability acceptance comes
from the user-approved baseline, whose behavior is unchanged.

These checks retain the previous targeted acceptance scope. They do not claim
exhaustive physical arrangements, sustained RF/load qualification or measured
acoustic performance. Detailed private operational evidence stays outside the
tracked release content.
