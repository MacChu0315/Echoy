# 方案 B v3 — 录制与播放修正

## 修改
在准确提供的 `echoy-arrange-B-v2.html` 上改动。源码解包后的构建内容先与v2逐字节核对一致，再开展修改。v2和更早文件均未覆盖。

1. 首页顶端增加“录一段”。录制时钟不由敲击建立：点击后解锁音频，预备两拍，随后自动记录四拍。记录原始时间相对于此独立起点计算，因此开始的空拍不会被抹掉。
2. 中央区域平时只试奏；预备期的敲击也只试奏，不计入。录制期间才写入。计时提示音使用独立本地音源，不写入音符计划，按本机音量输出，取消时清除未来提示音。
3. 录制期间原入口变为“取消”；空录、取消保留旧节奏，不自动恢复播放。首轮录制完成仍只附和一次，不自动启用持续演奏。
4. 主播放按钮改为无文字的▶/Ⅱ。录制期间它不可用，取消由独立入口承担。角色页试听的停止状态也统一为暂停，不再把“循环”和“静音”做成一对动作。
5. 本机暂停不改写共同时间原点；所有设备暂停以后，再次播放也对齐已经建立的拍点。每台独立输出与旧版的单次试听/循环权限保持分开。
6. 增加取消保护：准备中的自动试听携带本机操作序号。取消或暂停之后，迟到的渲染结果不能重新发声。录制中若接入左邻，取消此次录制，保留原内容，继续遵守原来“跟随左侧时不录本地输入”的规则。

原十二种附和、合成器、音量匹配、角色图形代码和基础样式保持字节一致；只新增计时提示音。空间接触类保持原样。显示仍为480×480/R60，300px中央绘图/16格反馈、64px窄滑条及底部角色/设置按钮位置不变。新增入口放入原首页标题区，不重做页面。

新增回归首先在v2失败：中央敲击会启动录制、没有首页录制入口、底部带循环/静音文字、录制等待首个敲击。另外，全部暂停后播放会重设时基。修复后同一问题的检查通过。

浏览器用真实鼠标在录制进入第二拍后敲击，验证输入第一落点不在第0格。随后完整附和和传给右邻的计划保留开头空拍。实际离线音频验证第一拍样本静音，并且后面确实发声；每种表达输出峰值受限。新增提示音的实际Analyser信号非零；取消之后，不再有未来提示声或录入。

初次长多机回归被工具超时终止，不计为通过，之后完整重跑44项通过。音频夹具最初返回函数导致工具提前调用，改为不返回函数，产品不因此修改。截图最初受分数像素边界影响得到481px高，改为截取准确的480×480区域，没有缩放产品。

## 未验证与既有约束
- 没有真机、固件编译、GPIO或无线声学同步验证。共享浏览器时钟不代表硬件多机时钟已验证。
- 工具浏览器对直接file://导航返回ERR_BLOCKED_BY_ADMINISTRATOR，没有绕过。交互与音频检查通过载入交付HTML相同内容执行。
- 仍使用固定96BPM/16格录入，极快落在同格的敲击可能合并；没有更改量化算法。
- 两侧64px控制宽度沿用原版，未宣称满足84px触控下限。
- 新的录制时钟有两拍本地预备；输出、重新播放和配置提交依原多机边界对齐。本轮不声称新增“多设备同时录制”的协调协议。

## 固件映射
| HTML行为 | 设备端对应 | 真机验收 |
|---|---|---|
| 独立录制与两拍预备 | 应用录制状态机、触摸事件时间戳、本地音频时钟 | 预备/录入边界误差、首拍留空、空录与取消 |
| 提示声不进入输入 | 音频输出提示源与触摸录入数据分离 | 提示声反馈、零音量、取消与后台安全 |
| 本机播放/暂停 | 本地输出权限、已建立的共同拍点 | 本机停止不影响同伴，再开按共同拍点进入 |
| 迟到准备取消 | 操作序号/任务世代校验 | 连续点击、准备失败、切角色、恢复不自播 |

所有功能仍为独立HTML实验；未改动factory/Recovery，也未生成或刷写固件。
