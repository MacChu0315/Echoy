# 方案 B v4 — 合并式控制条：验证与边界

## 基础与范围

以提供的 `echoy-arrange-B-v3.html` 为输入。先从v3包内源文件复建并逐字节比较，确认是同一个HTML，再施加增量修改。采用用户认可的暖白三状态合并控制条参考图；没有改成黑色/手机比例，也没有调用图像生成替换图形。

新增 `src/merged.css`、首页控制条模板和 `updateStrip()` 表示层方法。录制、播放、暂停、取消仍调用原来的 `arm()` / `transport()` / `mute()`，不是另外维护一份录音/播放状态。

## 修改

1. 顶部删除独立录制/取消入口；角色与表达在左上合成一行，电量保留右上。演奏区从113px上移至89px；声形/16格反馈仍是300px宽。
2. 底部两侧为84px角色/设置按钮，中间为244×84px合并控制条。空闲两个分段各122×84px；忙碌时整条244×84px为单一操作。不活跃的按钮即时 disabled、inert、移出键盘顺序与辅助读取，不只是透明遮盖。
3. 预备/录入时全条“取消”；准备试听、一次试听、循环播放时全条“暂停”。没有播放内容或跟随左邻时，原有禁用规则保留。
4. 视觉变化约240ms，输入权限不等待动画。取消/暂停能在形变中生效；焦点跟随新动作，并在结束时回到相应分段。减少动态效果偏好会关闭形变。
5. 去掉被要求删除的节拍点下方那句说明。正常播放/静止时不再反复解释按钮；预备、录入、等待生效、等待拍点、一次试听、取消/失败等信息保留在紧凑状态行。一次试听明确提示结束自动停，不与持续重复混为一谈。
6. 仅同步必要的“录一段”→“录制”使用说明；完整角色与表达页、设置结构、绘图函数和多机逻辑不变。

## 源码保留证明

`baseline/core.js`、`baseline/spatial.js`、`src/arrangement.js`、`src/audio.js`、原基础样式、桌面样式和外部HTML均与v3相同。`arm/tap/tick/transport/preview/mute`及其相关控制代码逐字节相同；末尾键鼠/手势/绘图帧/拖拽事件也相同。角色页模板逐字节保留。

来源和输出的哈希、原始文件未覆盖检查位于 `evidence/manifest.json`、`evidence/preservation.json`，完整差异位于 `evidence/v3-to-v4.diff`。

| 布局、状态和过渡 | 143/143 | 中英文十二表达、控件边界、轨道居中、形变中间帧/打断、窄屏不缩放、失败恢复 |
| 三台实际交互回归 | 44/44 | 鼠标录入、拖入/换位/拆开、单次试听、循环、局部暂停、下游变化、导出与故障 |

以上为断言数量，含循环条件检查；不是用户数量、审美评分或真机验证。浏览器执行的是最终交付HTML的同一份内容。

新控制条测试先在v3失败于没有合并控制区，修复后通过。布局检查又发现1px实体边框把两个分段热区高度从84px扣到了82px，复现后将边线改为不占空间的内描边，最终热区为84px高。多机/音频旧测试仅将点击定位改为当前可用按钮（`:enabled`），音乐、停止与计划断言没有放宽。

一次试听测试最初在音频开始前的等待拍点状态读取“试听一次”，修正为等待其实际进入发声状态后检查。源文件验证脚本的一次相对路径错误已纠正为绝对路径，未因此修改产品。

## 尚未验证及保留限制

- 未验证真机的触摸精度、屏幕可读性、声音和无线同步；未编译或刷写固件。
- 直接 `file://` 导航在工具浏览器里返回 `ERR_BLOCKED_BY_ADMINISTRATOR`，未绕过，也不计为通过。交互/声音检查使用 `set_content` 载入同一份交付内容。普通使用可打开HTML，但本轮不宣称已通过操作系统双击文件验收。
- 两侧64px滑块沿用现有设计，低于原84px建议触控宽度；本次没有擅自加宽。中央两分段在同一个连续控制条内相邻，共用边界，未额外插入12px间距。
- 仍为固定96 BPM、16格录入，极快同格敲击可能合并；没有更改录制量化、音量匹配或十二表达。
- 没有把该UI研究升级为正式v5.2.0或覆盖v5.1.0。
