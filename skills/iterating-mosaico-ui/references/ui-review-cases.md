# 设计迭代反例与验收

## 不同判断不能互相替代

Echoy v5.0.5 历史复核记录过下列问题。它们是方法案例，不是本轮对旧版或当前产品的重测结论。

| 实现检查 | 仍需回答的问题 | 下一步 |
|---|---|---|
| 容器中心对齐 | 主要声形是否成为视觉主体？ | 相同状态下比较全屏，结合实际作品作判断 |
| 按钮有底色与边框 | 新用户是否知道哪里能操作？ | 观察首次操作，不用样式存在代替用户观察 |
| 两处都能调整参数 | 同样位移是否同样效果，按下是否跳变？ | 相同起始值、位移、路径下操作并记录 |

两个输入原本有不同设计时，先指出差异和理由。不用“统一手感”悄悄改变确认过的行为。

## 局部比较示例

用户认可内容反馈，只认为顶部不协调。保留中央图形、控制规则、等待反馈和内容引擎，再比较两种顶部对齐关系。固定设备、语言、参数与暂停状态截图；随后进入运行和等待状态，检查标题变化是否跳动或遮挡。

一个可切换探索入口和几句说明就可能足够。两种方案都被拒绝时，复查是否把视觉重心问题误当成对齐问题，而不是马上再给十种颜色。

## 回归范围由改动决定

控件尺寸改变时检查灵敏度；页面结构改变时检查点击／滚动、返回、长文本、异步回调；视觉投影改变时检查显示的是当前内容还是待生效内容。只改文案也检查截断，但不要求重做完整产品定义。

分别说明实现了什么、设计判断是什么、哪些仍需人或硬件验证。历史通过数和图片精致度不能代替这些结论。
