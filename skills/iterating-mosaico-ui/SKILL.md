# 在认可基线上收敛 Mosaico 界面

## 适用范围

用于界面与交互迭代，不把审美判断当成已证实的质量指标。本技能是试用版；尚未完成独立 agent 的有／无 skill 对照。

沿用确认过的目标与设计，不为小修改重新访谈。先读取实际作品；目标图片或文件缺失时说明并索取目标，不凭文件名、旧描述或记忆重建后声称“原样恢复”。仅有截图时只评价可见内容，不推断动态行为。

## 工作方式

1. **锁定输入。** 核对用户指定文件、版本和当前工程；取得字节时记录提交号或校验值。文件名相近、版号更大不代表正确基线。
2. **划定本轮范围。** 明确保留什么、改变什么、尚待判断什么。保留项包含外观、状态反馈、手势和内容行为，不只是页面轮廓。已有记录直接引用；讨论不自动授权修改。
3. **提出少量原因假设。** 根据实际作品提出一到两个可比较的原因，如视觉重心被按钮抢走、对齐关系分裂、只读状态像按钮。区分设计判断与测量事实，不用长解释提前替用户决定喜好。
4. **用对照区分假设。** 方向未定时给少量结构上不同的方案；方向已定时集中处理主要问题。固定设备、语言、参数、运行状态和截图尺度。概念稿标明概念稿，运行截图来自实际页面。用户要求推荐时直接说明推荐与取舍。
5. **同时检查操作规则。** 区分可操作项与只读项；检查手势、刻度方向和参数变化。两处控制同一参数时核对相对／绝对输入、起点跳变和灵敏度；布局尺寸也会影响手感。有意保留差异时说明依据，不擅自统一后声称行为未变。
6. **覆盖小屏与动态状态。** 按当前契约检查圆角裁切、热区、关键文字、长英文、滚动、返回、边缘手势，以及适用的按住、等待、失败状态。视觉修改和语言切换不应意外重建运行中的内容或丢失已生效状态。
7. **保护基线并限制无效迭代。** 认可版本与探索分开。多轮被否定时回查目标和原因假设，不继续靠换色、加框、阴影或说明堆版本。形成决定只记录保留项、变化和理由，不把一次偏好升格为平台规则。

## 交付与验收

给实际修改或对照入口，说明保留项、关键变化、未解决问题。分别报告实现检查、基于作品的设计判断、真人观察和真机结果；未执行项明确写出。

居中、存在底色、断言通过只能证明对应实现条件，不证明视觉主体突出、第一眼可辨认或操作舒服。新布局回归已有动作与输出，不只测 CSS。未取得实际产品时，不声称完整恢复或功能无回归。
