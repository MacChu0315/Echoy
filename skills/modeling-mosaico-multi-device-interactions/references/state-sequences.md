# 状态与序列示例

以下是合成评审情景，不是固件、无线或音频测试结果。标识符仅表示职责，不要求采用这些名字。

## 准备中改主意并返回

假设现有内容 X 持续运行，用户先选 Y，再选 Z 并返回主页。Y 回调比 Z 晚到。

| 时刻 | 事件 | 预期 |
|---|---|---|
| t0 | X 已生效 | 当前内容为 X |
| t1 | 请求 Y，分配请求标识 | 显示准备 Y，不提前替换内容 |
| t2 | 请求 Z，旧请求失效 | 有效意图为 Z；按产品规则保留 X |
| t3 | 返回主页 | 保持用户选择的页面，不由回调强制导航 |
| t4 | Z 准备完成 | 仅在本项目允许时机提交 |
| t5 | Y 旧回调到达 | 不覆盖 Z、不跳旧页、不重启输出 |

另测 Z 失败、取消、用户停止和设备重启。内容意图有效性与页面导航权限分别检查。

## 局部拆开

假设 A—B—C 只解除断开的那条关系。断开 A—B 时，这条物理状态立即变化，B—C 不应重置。内容何时变由本项目决定，不默认保拍、等小节或立即静音。

待确认与明确分离不同。验证同时连接、多候选歧义、B 重启且旧消息晚到；不从模拟器全知信息替设备判断。

## 两个反例

多机专用游戏明确需要整组暂停：保留需求，定义权限、传播、确认、失败和恢复。即时本机响应不等待音乐边界；远端确认不能伪装成已经同步停止。

连续两次“计数加一”：两条命令通常都应保留，不合并成最后一次。它不同于选择 Y 后选择 Z。停止后旧播放请求完成，也不能自动恢复输出。

## 故障与来源

区分输出通路失败、内容数据失效和通信失联。允许保留有效内容时，单台扬声器失败不应自动让邻机失去内容；真实数据失效按预定规则降级。网络恢复不自动等于播放恢复。

依据已审议候选稿、其中的行为映射与 v5.0.5 验证记录，以及用户对未生效／已生效音乐的区别。原始代码和报告未复制进本包；序列仍需在新项目执行，历史结论不能代替新测试。
