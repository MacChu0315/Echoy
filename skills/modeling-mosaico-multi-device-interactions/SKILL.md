# 分清多机关系、用户意图与已生效状态

## 适用范围

仅在多机关系或异步竞争影响体验时使用；简单同步单机不需要会话模型。本技能是试用版；尚未完成独立 agent 的有／无 skill 对照。

以当前产品定义为准。左邻回应、拆开保拍、下一小节切换、没有整组暂停是 Echoy 案例，不是通用规定。沿用已有规则；关键策略缺失时提出具体取舍，不照搬音乐规则。

## 工作方式

1. **按需拆分状态。** 区分发现候选、物理接触与不确定性、逻辑会话、已生效内容关系、本机输出、未生效意图。只保留必要维度。接触变化可立即发生，内容变化遵守本项目时机，不用一个布尔值代替两者。
2. **明确作用范围。** 每种动作影响本机、某条连接还是整组。对端不明确时保留待确认，不凭信号、桌面坐标或未证实的测距能力猜对端。整组操作是否存在由产品决定。
3. **区分意图与命令。** 可替换设置意图分已收到、准备中、待提交、已生效；新有效意图可替换未生效旧设置。递增、记录、发送等不可丢命令不适用“只留最后一次”；分别定义顺序、幂等和失败处理。
4. **定义提交和取消。** 连续声画需要边界时说明边界、准备失败保留什么、如何反馈等待。即时停止或安全操作不能被“等边界”延误；还要阻止旧待执行动作随后恢复输出。
5. **阻止过期结果。** 用请求版本、取消标识、页面世代、设备启动世代或等价方法。分别检查回调是否对应有效意图、是否有权改变当前页面、是否接收了重启前旧消息。只换可见选中态不等于取消后台工作。
6. **让反馈对应事实。** 物理标记显示当前接触；内容画面显示已提交内容；待生效选择单独反馈。显示层读取状态，不因渲染改写关系或输出。输出失败不必然等于内容无效，按实际故障限定传播范围。
7. **回放动作序列。** 从明确初始状态验证快速改主意、准备中返回、第三台加入、局部拆开、多处同时变化、失联、重启旧消息和失败恢复。独立按钮检查不覆盖竞争；无关序列不强制加入。

## 交付与验收

给够用的状态／转移表、输入与可观察输出、关键序列和预期结果，可纳入已有设计或测试。分清已确认策略、实现选择和待验证假设。

逻辑模拟只证明给定事件下的规则，不证明真机磁吸匹配、无线对时或声学同步。超时与资源预算来自当前测量或明确假设。恢复按产品定义验收，不默认重播、全组重置或强制独奏。
